# GitTrend — Brand Voice

## Positioning

GitTrend is the evidence layer for open-source discovery. It scores and ranks
repos across GitHub and Codeberg with a multi-dimensional methodology —
release velocity, contributor concentration, issue responsiveness, docs
quality — and shows the number next to the repo. The brand is the scorecard,
not the hype cycle.

## Voice in one line

*A careful engineer with a query window open, mildly amused by the gap
between stars and substance.*

## Do

- Lead with the number and the query that produced it. "We score 4,185 repos.
  Here's what moved this week:" is a complete opener.
- Name repos and people. Credit is cheap and earns goodwill.
- Show methodology limits when they matter ("score measures maintenance
  signals, not code quality").
- Be specific: "TypeScript repos average 76.5; Rust averages 59.5" beats
  "TypeScript scores well".
- Use the taxonomy: green/yellow/red/critical verdicts, GitTrend Score,
  movers.
- Okay to be wry: "the top-scoring critical repos are all awesome-lists,
  which checks out."

## Don't

- No "revolutionary", "game-changing", "unlock", "supercharge".
- No hype-cycle framing ("the future of X is here").
- No dunking on maintainers or projects. Red verdicts describe signals, not
  people — always frame as "the signals say", never "this project is bad".
- No unverifiable claims. Every number traces to gittrend.db.
- No engagement bait, no "you won't believe", no threadsplaining.

## Signature formats

- **Weekly movers** (Tue): top 5 score gains with old→new numbers.
- **Methodology notes**: what a signal does and doesn't mean.
- **Counter-narrative data**: TypeScript > Rust on average score; awesome-list
  penalty.
- **Badge/feed plugs**: only inside genuinely useful posts, with the link.

## UTM convention

`?utm_source=<platform>&utm_medium=social&utm_campaign=weekly-movers-<yyyymmdd>`

## Platforms

- **X**: short, number-first, one link. Chart image optional but earns reach.
- **Bluesky**: same draft, slightly more conversational.
- **dev.to**: long-form methodology + data deep dives, charts embedded.
- **Reddit**: only in genuinely relevant threads, affiliation disclosed,
  answer-first (the data helps the thread, the link is secondary).
- **LinkedIn**: methodology and engineering-culture framing, no emoji storms.
